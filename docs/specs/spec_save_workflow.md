# Спецификация регламента сохранения (Save Workflow)

## 1. Назначение
Регламент автоматизированного переноса исходного кода и технической документации из интерфейса генеративной модели (LLM) в локальную файловую систему проекта tennis-pro. Перенос осуществляется через системный буфер обмена с помощью утилиты `scripts/save_clip.py` (вызываемой через терминальный алиас `save` или шорткат Raycast).

## 2. Стандарт формирования ответа генератора
Каждый ответ, содержащий файл для сохранения в проект, формируется по строгим правилам:
1. **Монолитный блок:** Ответ выдается единым неделимым блоком без вводных фраз, промежуточных пояснений и заключительных реплик.
2. **Обязательный маркер пути:** Первая строка ответа ВСЕГДА строго содержит директиву адресации:
   `### FILE: <относительный_путь_от_корня_репозитория>`
   *(Пример: `### FILE: src/js/core/audio.js`)*
3. **Запрет внешнего Markdown-обрамления для .md файлов:** При генерации файлов документации (`.md`) запрещается оборачивать весь ответ во внешние тройные обратные кавычки (```markdown ... ```). Текст начинается непосредственно с маркера `### FILE: ...`, чтобы исключить сбои синтаксического парсера стриминга и скрипта сохранения.
4. **Соблюдение регистра и путей:** Путь в маркере оформляется строго в соответствии со стандартом проекта: `snake_case`, латиница, без пробелов. Исключение — стандартные файлы корня (`README.md`, `CURRENT_STATE.md`, `CHANGELOG.md`).

2. В терминале вызывается изолированная команда:

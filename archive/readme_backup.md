# Теннисный Полигон (Tennis Pro)

Автономный цифровой комплекс тренера по теннису для прямого управления тренировочным процессом на корте (целевые устройства: iPad Pro, MacBook). Приложение спроектировано как автономное одностраничное веб-приложение (Single-File Monolith) без внешних зависимостей.

---

## 1. Главные правила проекта (Кодекс разработки)

1. **Правило чистого стола:** Никаких случайных файлов в корне проекта. Все новые материалы и черновые артефакты попадают во входящие директории.
2. **Один шаг за раз:** Работа ведется строго над одним модулем/файлом за итерацию. Не переходим к следующему этапу, пока текущий не проверен.
3. **100% Offline-First:** Приложение обязано работать в Safari на iPadOS без подключения к интернету. Данные сессий, ростера и настроек сохраняются исключительно локально (`localStorage`).
4. **Контрастность и эргономика:** Элементы управления оптимизированы для работы на солнце и быстрых нажатий на корте (крупные тач-зоны, четкий визуальный отклик, антидребезг).
5. **Строгий регламент артефактов и Git:** Все пути оформляются в едином стиле, а сохранение и фиксация изменений происходят по регламентированному протоколу.

---

## 2. Архитектурные инварианты

- **Zero-Dependency Monolith:** Приложение состоит из одного исполняемого файла интерфейса (`training_counter.html` / `index.html`). Внешние CDN, сторонние CSS/JS-библиотеки и внешние шрифты не используются.
- **Синтез звука Web Audio API:** Звуковые эффекты (таймер, клики, персональные звуки участников) генерируются процедурно через `AudioContext` (`OscillatorNode`, `GainNode`, `BiquadFilterNode`) без внешних звуковых файлов.
- **Touch-оптимизация под iPadOS:**
  - Обработка нажатий через нативный `touchstart` с `passive: false` и отменой стандартного поведения (устранение задержки 300 мс).
  - Аппаратный/программный антидребезг (debounce 500–700 мс) на карточках ввода очков.
- **Медиа-дистрибуция:** Генерация вертикальных карточек Stories на HTML5 Canvas (9:16, 1080×1920) и прямая отправка протоколов в родительский канал через Telegram Bot API при наличии сети.

## 3. Регламент генерации и сохранения артефактов

В проекте действует обязательный протокол взаимодействия с кодовой базой:

1. **Формат выдачи файла:**
   - Модель отдает сохраняемые файлы единым монолитным блоком.
   - Первая строка блока содержит строго:
     ```text
     ### FILE: <относительный_путь>
     ```

2. **Изоляция команды сохранения:**
   - Сохранение выполняется исключительно вызовом:
     ```bash
     save
     ```
   - Запрещено указывать имя файла в аргументах команды `save`, объединять ее с текстом коммита, комментариями или операторами сцепки (`&&`, `;`).

3. **Раздельные команды терминала:**
   - Команды выдаются строго по отдельности, без оператора `&&` и без многострочного heredoc (`cat << 'EOF'`).

4. **Правило именования путей (Правило 6):**
   - Все относительные пути к файлам и каталогам пишутся строго в `snake_case`.
   - Пробелы, спецсимволы и кириллица в путях кода и артефактов запрещены.

## 6. Модули комплекса

1. **Ростер и Сессия:** Чекин присутствующих (2–8 детей), профили с фото/звуками.
2. **Табло касаний (Matrix Counter):** Скоростной подсчет с цветовыми вспышками и звуком.
3. **«Аладдин и сокровища корта»:** Сбор мячей в сквозную казну дня.
4. **Секундомер со штрафами:** Заезды/полоса препятствий с фиксацией ошибок на лету.
5. **«Однорукий бандит»:** Прием серий ударов, джекпот и барабан ОФП-заданий.
6. **«Экспертная машина»:** Взаимная оценка техники ударов по 3 биомеханическим критериям.
7. **Итоги дня и медиа-центр:** Генерация карточек Stories (1080×1920) и отчет в Telegram.

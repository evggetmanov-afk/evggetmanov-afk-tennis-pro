# Теннисный Полигон (Tennis Pro)

Автономный цифровой комплекс тренера по теннису для прямого управления тренировочным процессом на корте.

- **Целевые устройства:** iPad Pro, MacBook.
- **Архитектурный стек:** 100% Offline PWA, Vanilla JS (ES6+), процедурный Web Audio API, IndexedDB.
- **Сборка:** Zero-Dependency монолит (`scripts/build.py` компилирует проект в единый `index.html`).

---

## 1. Кодекс разработки (Инварианты)

1.1. **Чистый корень и изоляция сырья:**
В корне репозитория допускаются только стандартные документы (`README.md`, `CHANGELOG.md`, `CURRENT_STATE.md`), файл сборки (`index.html`) и системные конфиги (`.gitignore`). Папка `inbox/` является изолированным буфером для сырых заметок, внешних выгрузок и прототипов-доноров. Модель и скрипты игнорируют `inbox/`, если конкретный файл не запрошен оператором явно.

1.2. **Один шаг за раз:**
Разработка ведется строго по одному изолированному модулю за итерацию. Переход к следующему компоненту разрешен только после верификации и тестирования текущего.

1.3. **100% Offline-first & PWA:**
Комплекс функционирует автономно без постоянного сетевого соединения и оформляется как PWA с установкой на экран «Домой» iPadOS. Для защиты от стирания данных при нехватке памяти Safari/WebKit реализуется обязательный механизм ручного резервного экспорта базы в файл (JSON).

1.4. **Контрастность и эргономика корта:**
Интерфейс рассчитывается на работу под прямым солнечным светом и управление в динамике тренировки:
- Крупные сенсорные зоны (минимальный тач-таргет 48–64 px).
- Высококонтрастная палитра и четкая типографика.
- Мгновенный звуковой и визуальный отклик на любое действие.

1.5. **Стандарт именования путей (snake_case):**
Имена всех рабочих директорий, файлов исходного кода, модулей, стилей и скриптов оформляются строго строчной латиницей через нижнее подчеркивание (`snake_case`) без пробелов и спецсимволов. Исключение — стандартные корневые документы (`README.md`, `CHANGELOG.md`, `CURRENT_STATE.md`, `.gitignore`).

1.6. **Маршрутизация контекста:**
- Архитектурный закон зафиксирован в `README.md`.
- Оперативный фокус, спринты и временные договоренности ведутся в `CURRENT_STATE.md`.
- Детальные контракты и схемы модулей выносятся в `docs/specs/`.
- Дорожная карта и реестр тренировочных механик зафиксированы в `docs/roadmap.md`.
- Формирование файлов для локального сохранения выполняется строго по регламенту `docs/specs/spec_save_workflow.md`.

1.7. **Надежность терминальных операций (Fail-Fast):**
- Зависимые цепочки команд связываются оператором `&&` для немедленной остановки при сбое любого звена.
- Массовые операции над файлами выполняются единой командой с явным перечислением аргументов (`mv f1 f2 target_dir/`).

## 2. Архитектурные инварианты комплекса

- **Модульная кодовая база → Монолитная сборка (Zero-Dependency):**
  Исходный код пишется в модульной структуре (`src/css/`, `src/js/core/`, `src/js/modules/`). Локальный скрипт `scripts/build.py` собирает все ресурсы в монолитный файл `index.html` без внешних библиотек и пакетных менеджеров.

- **Двухуровневое хранилище (IndexedDB + localStorage):**
  - Ростер спортсменов, профили, фотографии и архив тренировок сохраняются в IndexedDB.
  - Временное состояние активной сессии кэшируется в `localStorage`.
  - Синхронизация транзакций выполняется с приоритетом надежности IndexedDB.

- **Звуковой движок и Audio Lifecycle (Web Audio API):**
  - Звуковые эффекты генерируются процедурно через `AudioContext` (`OscillatorNode`, `GainNode`, `BiquadFilterNode`).
  - Обязательный однократный вызов `audioCtx.resume()` по первому тапу оператора.
  - Предусмотрена обработка прерываний (`interrupted`) при блокировке экрана iPad и восстановление аудио-контекста при пробуждении.

- **Эргономика сенсорного ввода (Pointer Events):**
  - Интерактивные элементы обрабатывают событие `pointerdown` с CSS-свойством `touch-action: manipulation` (исключение системной задержки тапа 300 мс).
  - На скоростных экранах подсчета реализован аппаратный throttle (100–120 мс) по `pointerId` для отсечения дребезга сенсора.

- **Изолированный экспорт Canvas Stories:**
  - Отрисовка графических карточек итогов (1080×1920, 9:16) выполняется по требованию в отдельном буфере (`OffscreenCanvas` / скрытый холст) с немедленным освобождением контекста для защиты WebKit от лимитов памяти GPU.

- **Сетевой слой (Outbox Queue):**
  - Любые внешние интеграции (выгрузка отчетов, отправка данных) проектируются по принципу отложенной локальной очереди, срабатывающей только при обнаружении стабильного интернет-соединения.

## 3. Структура репозитория

```text
tennis-pro/
├── README.md                           # Архитектурная конституция проекта
├── CHANGELOG.md                        # Хронологический журнал изменений
├── CURRENT_STATE.md                    # Оперативный статус и фокус сессии
├── .gitignore                          # Исключения (.DS_Store, .obsidian/)
├── index.html                          # Скомпилированный автономный дистрибутив
├── docs/                               # Утвержденная техническая документация
│   ├── roadmap.md                      # Дорожная карта и реестр модулей
│   ├── adr/                            # Архитектурные решения (ADR)
│   └── specs/                          # Спецификации модулей и протоколов
│       └── spec_save_workflow.md       # Регламент сохранения через скрипт save
├── src/                                # ЕДИНСТВЕННЫЙ каталог исходного кода
│   ├── css/                            # Стили интерфейса
│   │   └── components/                 # Стили отдельных модулей
│   ├── js/
│   │   ├── core/                       # Ядро: Audio Engine, Storage, Session
│   │   └── modules/                    # Изолированные экраны тренировки
│   └── assets/                         # SVG-иконки и встроенные графические ресурсы
├── scripts/                            # Инструменты автоматизации
│   ├── build.py                        # Локальный сборщик модулей в монолит
│   ├── save_clip.py                    # Движок сохранения из буфера (алиас save)
│   ├── log.py                          # Утилита ведения журнала
│   └── raycast_save_clip.sh            # Скрипты интеграции с Raycast
├── inbox/                              # Изолированный буфер входящих сырых материалов
└── archive/                            # Резервные копии и архивные версии
```

## 4. Архитектура модулей

Комплекс строится по принципу независимых мини-приложений (виджетов тренировки), подключаемых к единой шине состояния и ядру (`src/js/core/`).

Актуальный реестр модулей комплекса, их фазы реализации и функциональные требования вынесены в отдельный документ: **`docs/roadmap.md`**.

Актуальный фокус спринта, задачи текущей рабочей сессии и временные пометки фиксируются в **`CURRENT_STATE.md`**.
